# 2026-08-11 — Publishing images and videos directly

Media files can now be published without a note around them (issue #13). A `file-menu` handler adds "Publish to Typefully" when the right-clicked file is a publishable image or video, a `files-menu` handler does the same for a multi-file selection ("Publish N files to Typefully"), and a `publish-media-file` command covers the file currently open. All three funnel into `publishMediaFiles(files)`, which creates a single draft with `text: ''` and every uploaded `media_id` attached, in selection order.

What counts as publishable media lives in `classify-media-file.fn.ts`: `getMediaKind()` maps an extension to `'image' | 'video' | null` against the new `MEDIA_IMAGE_EXTENSIONS` / `MEDIA_VIDEO_EXTENSIONS` constants. It is deliberately narrower than `MEDIA_MIME_TYPES` — PDFs stay uploadable as note attachments but are not offered as a standalone post. `mov` and `webm` were added to `MEDIA_MIME_TYPES` at the same time: mp4-only would have made "publish a video" mostly theoretical.

Ordering matters for the guards. Platform limits are checked with the existing `checkMediaLimits()` **before** any upload, for the same reason as the note path: a draft rejected after the uploads leaves orphaned media on Typefully. After that, `describe-media-selection-warning.fn.ts` flags two selections that the platforms disagree about — several videos, and a video mixed with images. Most platforms accept one video per post and refuse mixed media, but not all do, so this is a `ConfirmModal` the user can dismiss rather than a hard block. Individual upload failures are reported per file and skipped; publishing only aborts when nothing uploaded at all.

`TFile` had to move from a type-only import to a value import in `plugin.ts` — the menu callbacks receive a `TAbstractFile` and need `instanceof` to narrow it.
