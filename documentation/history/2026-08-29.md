# 2026-08-29: Catalog alignment + declarative settings port (fleet review)

## Accomplished

Two commits from the fleet-review pass (obsidian-plugin-template is the canonical source):

1. **Catalog reviewer alignment (A-E)**: `__PLUGIN_CHANGELOG__` build define replaces the markdown import (the reviewer's older Bun cannot parse the import attribute); eslint-plugin-obsidianmd 0.1.9 → 0.4.1 with `ui/sentence-case` as an error — the publishing platforms and Typefully's own feature names (Threadify, AutoRT, AutoPlug) declared as brands, anchored exemptions for quoted commands, menu paths and placeholders, and real copy fixes (the Auto retweet/plug/scheduling toggles and the "Social Set ID" strings dropped their title case); type roots pinned + obsidian typings 1.13.1; `bun audit` clean — the overrides block pinned fast-uri, js-yaml and brace-expansion AT vulnerable versions and was hand-corrected; template toolchain carrying the fleet's sourcemap-`'none'` and versions.json latest-floor fixes.

2. **Declarative settings port (feat!, minAppVersion 1.8.7 → 1.13.0)**: `getSettingDefinitions()` replaces the 820-line `display()` tab across all seven sections. Plain controls where the framework can own them (toggles, dropdowns, text, textarea, color); render rows where a row needs more than one control or a masked input (API key, social-set input + Load button, the paired custom-color pickers, link color with its conditional reset); `visible:` hooks for the conditional custom-gradient/card/font rows; row `action:` for the "click a social set to use it" entries. Nested settings are addressed through explicit prefixed keys (`platform:x`, `screenshot:background`) rather than dot paths, so an unknown key can never resolve into an object.

    The write path is now a single serialized persist-then-commit `updateSettings(mutator)`: memory swaps only after `saveData()` succeeds, and each mutation derives from the previously committed state. The platform toggles compute `enableAllPlatforms` INSIDE the mutator — concurrently enabling the last two platforms must end with the flag set, which a pre-await snapshot gets wrong.

    Async work (API-key validation, tag loading) writes into its own row instead of re-rendering, so a slow API cannot replace text the user is typing, and both paths are guarded on `containerEl.isConnected` because Obsidian also calls `getSettingDefinitions()` when it registers the tab for settings search.

## Breaking change

`minAppVersion` rises from 1.8.7 to 1.13.0: the declarative settings API does not exist on older Obsidian versions, so the settings pane cannot render there at all. The README states the requirement, and the release notes for the next version must call it out — users below 1.13 keep the previous release through `versions.json`.
