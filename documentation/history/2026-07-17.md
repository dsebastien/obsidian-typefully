# 2026-07-17 — Two-phase release workflow

Ported the fixed `release.yml` from `obsidian-remarkable-sync` (verbatim; the old file was byte-identical to the shared original). The old workflow built and attested artifacts at the triggering commit and only then created the version-bump commit and tag, so the build-provenance attestation was bound to a different commit than the release tag — the community-catalog review rejected releases with "attestation failed cryptographic verification". The new design runs a `prepare` job (dispatch on a branch: bump, changelog, format, build+test gate, commit, lightweight tag, re-dispatch at the tag) and a `publish` job (dispatch-at-tag or bare tag push: build, attest without `continue-on-error`, release at `github.sha` == tag commit). Design proven live on remarkable-sync 1.5.0 (cert sha == tag commit). Also updated the workflow summary printed by `scripts/release.sh`.
