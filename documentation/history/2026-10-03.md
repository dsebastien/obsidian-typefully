# 2026-10-03: API key moved to Obsidian SecretStorage

## Accomplished

- `PluginSettings.apiKey` replaced by `apiKeySecretName` (default `typefully-api-key`) plus `legacySecretMigratedAt`. The value is read at use time via `plugin.getApiKey()` (`app.secretStorage.getSecret`), never cached in settings.
- Per-device migration (`src/app/utils/api-key-secret.fn.ts`, `migrateLegacyApiKey`) runs on every load: if this device's secret is absent ('' counts as absent: there is no delete API), it is bootstrapped from the legacy plaintext `apiKey` still in data.json. The plaintext copy is kept as a read-only bootstrap source so other synced devices migrate on their next start; it is never written with a new value.
- The plaintext copy is dropped: 60 days after the first migration (`legacySecretMigratedAt`), via the "Remove plain-text copy now" button, when the secret is rotated (a different value under the name after a migration was recorded), when another secret is selected, or on "Clear" (which also blanks the device secret).
- First migration never overwrites a different secret already stored under the default name (another vault on the same device): it uses `typefully-api-key-2`, `-3`, ...
- If SecretStorage rejects the write, the plaintext stays in memory and on disk and the next load retries.
- Settings row uses `SecretComponent` via `setting.addComponent`. minAppVersion already 1.13.0 (>= 1.11.4).

## Verification

Unit tests for the pure migration (`api-key-secret.fn.spec.ts`) and plugin-level multi-device scenarios (`settings/api-key-migration.spec.ts`: device B bootstrap, rotate, clear, 60-day purge, button purge, store failure).
